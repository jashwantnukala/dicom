# DICOM Receiver + Pusher — Windows EXE Build

This repo is set up to automatically build a Windows `.exe` using GitHub
Actions + PyInstaller — no local Windows machine needed.

## Files
- `dicom_receiver_pusher.py` — main app
- `lucide_icons_data.py` — icon data used by the app
- `logo.png` — app logo (also converted to `icon.ico` for the exe icon)
- `requirements.txt` — Python dependencies
- `.github/workflows/build-exe.yml` — GitHub Actions workflow that builds the exe

## How to get your EXE

1. **Create a new GitHub repo** (public or private) and push these files to
   the `main` branch:
   ```
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<your-repo>.git
   git push -u origin main
   ```

2. **Go to the "Actions" tab** on your GitHub repo. The workflow
   **"Build Windows EXE"** will run automatically on push (it also runs on
   demand — click "Run workflow" if you want to re-trigger it manually).

3. **Wait for the build to finish** (a few minutes). Open the completed run,
   scroll to **Artifacts**, and download **`DICOM_Receiver_Pusher-windows-exe`**.
   Unzip it to get `DICOM_Receiver_Pusher.exe`.

4. Run the `.exe` on any Windows machine — no Python install needed there.

## Notes / things to double check after your first build
- The app is bundled with `--onefile --windowed` (no console window). If you
  ever need to see console output/errors for debugging, temporarily remove
  `--windowed` from the workflow, rebuild, and run from a terminal.
- Optional packages (`psutil`, `pyzipper`, `ldap3`, `matplotlib`, `reportlab`,
  `python-gdcm`, `pylibjpeg*`, `tkinterdnd2`) are installed via
  `requirements.txt` so the exe should support all optional features. If you
  don't need one of them, you can remove it from `requirements.txt` to shrink
  the exe.
- `sopclass.ini` is generated by the app itself at first run — it does not
  need to be bundled.
- If the exe fails to start on a clean Windows machine with an import error,
  it's almost always a missing PyInstaller "hidden import" or "collect-all"
  for that package — add `--collect-all <package>` to the workflow's
  `Build EXE` step and re-push.
- The GitHub Actions free tier includes generous minutes for public repos;
  private repos have a monthly minute quota depending on your plan.
